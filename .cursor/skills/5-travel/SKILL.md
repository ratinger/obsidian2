# 5_travel — 旅行行程＋見取り図（フォルダ単位）

宿泊・移動・日別行程の Markdown と、周辺スポットの Leaflet 見取り図（`_map.html`）を、  
**日付＋場所のフォルダの中**にまとめて作る。

名古屋（`/3_nagoya`）・八千代（`/4_yachiyo`）の定型往復は専用スキルを優先する。それ以外の旅行・街歩き用。

## いつ使うか

- `/5_travel` または「5_travel」と言われたとき
- ホテル泊・街歩き・買い物ルートをまとめたいとき
- 本屋・家電・金券・食事などの配置マップが欲しいとき

## 基本イメージ（必ず守る）

```
出発日・帰宅日・場所を入力
    ↓
14_旅行/{出発日YYYYMMDD}_{場所}/   ← フォルダを先に作る
    ├── {出発日YYYYMMDD}_{場所}.md
    ├── {出発日YYYYMMDD}_{エリアA}見取り図_map.html
    └── {出発日YYYYMMDD}_{エリアB}見取り図_map.html
```

- フォルダ名・主ファイル名の日付は **出発日** の `YYYYMMDD`
- 行程メモのタイトル・日別セクションには **出発日〜帰宅日** の期間を明記する
- `{場所}` = ユーザーが言ったエリア略称（例: `大塚池袋`）
- 成果物は**すべてこのフォルダ内**。親の `14_旅行/` 直下にバラまかない
- 日帰り（出発日＝帰宅日）も同じルール

完成例:

```
14_旅行/20260811_大塚池袋/
  ├── 20260811_大塚池袋.md          ← 中身は 8/11–13 の期間で書く
  ├── 20260811_大塚見取り図_map.html
  └── 20260811_池袋見取り図_map.html
```

## フェーズ 1: 問答で情報をそろえる（必須）

**与えられていない情報は推測で埋めない。** 問答で確定してからファイルに書く。

### 問答ルール

- 不足は質問する。一度に聞きすぎない（目安 3〜6 項目）。続きは次ターンで聞く
- 「未定」「後で」はそのまま扱い、勝手に仮置きしない（メモには「未定」と書くか欄を空ける）
- **個人固有の情報**（予約番号、同行者、希望時刻、好み）は必ずユーザー確認
- **公開情報**（店舗の住所・営業時間、一般的な路線）は Web 調査してよい
- ユーザーが既に書いた内容・添付PDFから取れる内容は聞き直さない

### 第1問（ゲート）— これ無しではフォルダも本書きもしない

1. **出発日**
2. **帰宅日**（日帰りなら出発日と同じ）
3. **場所**（フォルダ名用略称）

### 追加問（書くのに必要なものだけ）

足りない項目だけ聞く。例:

| 項目 | 例 |
| --- | --- |
| 宿泊 | ホテル名、予約番号、IN/OUT |
| 交通 | 特急の有無、予約、希望の発着帯 |
| 同行 | 人数・同行者 |
| スポット | 本屋・家電・金券・食事・観光のどれを載せるか |
| 日別 | 各日のやりたいこと・固定予定 |
| 成果物 | 既定は行程メモ＋`_map.html`＋Googleマップリンク |

第1問が揃い、行程に必要な追加情報もそろった（または未定として明示された）ら次フェーズへ。

## フェーズ 2: フォルダ作成

1. 出発日から `{出発日YYYYMMDD}` を確定。帰宅日も記録する
2. 場所名をフォルダ用に整える（空白除去。必要なら短い日本語略称）
3. `14_旅行/{出発日YYYYMMDD}_{場所}/` を作成
4. 以降のファイルはすべてこのフォルダに書き込む

## フェーズ 3: 調査

Web で確認する（記憶や古いメモだけで断定しない）:

| 調べるもの | 優先ソース |
| --- | --- |
| ホテル・予約 | 予約確認・公式 |
| 列車・特急 | 公式時刻表／予約確認。曜日ダイヤに注意 |
| 店舗の住所・営業時間 | 公式店舗ページ |
| 施設の位置関係 | 公式アクセス文＋地図 |
| 地図ピン座標 | **OpenStreetMap（Overpass 等）の施設・建物中心を優先**。無い場合のみ住所から概位とし、ポップアップに「概位」と書く |

**位置の注意**

- 「駅直結」「百貨店内」と「同ビル／隣接地」を混同しない（例: ヨドバシ池袋は西武店内テナントではない）
- 東西口・南北口の覚え方がある街は、行程メモ冒頭に1行で書く
- 地下街・別館は地上ピンがずれることがある → 南館／本館など建物名で確認

## フェーズ 4: 行程メモ作成

### 出力パス

`14_旅行/{出発日YYYYMMDD}_{場所}/{出発日YYYYMMDD}_{場所}.md`

- タイトルは期間で書く（例: `20260811–13 大塚・池袋`）
- 日別セクションは出発日〜帰宅日の各日を作る
- 見取り図 `_map.html` へのリンクは**同フォルダ相対**（ファイル名だけ）

### 必須セクション（この順を基本）

1. **ヘッダ** — 同行者、宿、予約番号、注意（特急券＋乗車券など）
2. **見取り図リンク** — 同フォルダの `_map.html` への相対リンク
3. **0. 予約一覧** — ホテル・列車などの表
4. **0.5 主要ポイント（Googleマップ）** — スポット名と `[地図](https://www.google.com/maps/search/?api=1&query=...)` の表（エリア別に分けてよい）
5. **日別行程** — `| 時刻 | イベント | 注意事項 |`
6. **スポット詳細** — 必要に応じて金券／家電／本屋などの営業時間表
7. **持ち物・注意**

### Googleマップリンクのルール

- **行程メモ本体に書く**（見取り図専用の別 Markdown は作らない）
- クエリは店名・施設の検索で一意になる文言にする
- ホテル表にも `地図` 行を入れてよい

## フェーズ 5: 見取り図 `_map.html`

### 出力パス

`14_旅行/{出発日YYYYMMDD}_{場所}/{出発日YYYYMMDD}_{エリア}見取り図_map.html`

拠点が複数エリアにまたがる場合は `_map.html` をエリアごとに分ける（例: 大塚／池袋）。

### 作るもの／作らないもの

| 作る | 作らない（既定） |
| --- | --- |
| Leaflet + OSM Japan タイルの `_map.html` | 見取り図専用 `.md` |
| | `.png` / `.jpg` 書き出し |
| | `.kml`（ユーザーが明示した場合のみ） |
| | `14_旅行/` 直下へのバラ置き |

### `_map.html` の要件

- 既存の `*_見取り図_map.html` をベースに複製して地点だけ差し替える
- カテゴリ色分け（駅／宿／本屋／家電／金券／食事 など）
- ラベル＋ポップアップ（住所・根拠・「概位」注記）
- エリアラベル（東口／西口、北口／南口など）
- `fitBounds` で主要ピンが入る初期表示
- 座標は OSM 確認後に入れる。疑わしいピンは調査し直す

### Leaflet ひな形の要点

```html
<!-- unpkg leaflet 1.9.x / tile: https://{s}.tile.openstreetmap.jp/{z}/{x}/{y}.png -->
<!-- places = [{ name, cat, lat, lng, note? }, ...] -->
<!-- colors by cat; circle markers + text labels; fitBounds -->
```

## 検証チェックリスト（出力前）

- [ ] 未提供の個人情報を推測で埋めていない（問答または「未定」）
- [ ] `14_旅行/{出発日YYYYMMDD}_{場所}/` を先に作り、成果物がその中だけにある
- [ ] 出発日〜帰宅日の期間がヘッダ・日別に反映されている
- [ ] 日付・曜日と列車ダイヤが一致（土休日まとめにしない）
- [ ] 予約番号・発着・座席を予約確認と照合した（渡されている場合）
- [ ] 主要店の営業時間を公式で確認した（変更注記あり）
- [ ] 地図ピンを OSM 等で見直し、デパート内誤認がない
- [ ] `_map.html` 以外の見取り図ファイルを増やしていない
- [ ] Googleマップリンクが行程メモ本体にある
- [ ] 行程メモ先頭から `_map.html` に辿れる（相対リンク）

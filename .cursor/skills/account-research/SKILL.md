# account-research — 企業・団体調査

企業・団体の公開情報を手順どおり調べ、信頼性を評価する調査報告書を作る。  
LLM 非依存の作業プロトコルとして実行する（Claude / GPT / Gemini 共通）。

## いつ使うか

- ユーザーが企業・団体の調査、信頼性確認、会社・クリニック・業者などの下調べを依頼したとき
- `/account_research` または「account-research」と言われたとき

## 入力

最低限、調査対象の **名称** が必要。分かれば次も使う:

- 公式サイト URL / ドメイン
- 所在地・代表者名
- 調査の焦点（例: 許認可、トラブル有無、業界登録）

名称だけでは特定できない場合は、候補を示して確認してから本調査に進む。

## 情報源の優先順位

上から順に優先する。下位ソースだけで上位を覆さない。

1. **公式サイト**（会社概要、所在地、代表者、事業内容、お知らせ）
2. **法人情報**（法人番号公表サイト、登記・商業登記に関する公開情報）
3. **官公庁・自治体**（許認可、届出、行政処分、指導、公表リスト）
4. **業界団体・資格登録**（加盟・認定・登録の有無と掲載内容）
5. **ニュース・報道**（信頼できる媒体を優先。日付・媒体名を記録）
6. **口コミ・評判**（補助情報のみ。単独では断定しない）

Vault 内（`01_index/index.md` / `02_stored/`）に関連ノートがあれば参照し、報告書に「Vault 既存メモ」として区別して書く。

## 調査手順

次の順で進める。スキップした項目は報告書に「未実施」と理由を書く。

1. **対象の特定** — 正式名称、別名、公式ドメインを確定
2. **公式サイト** — 会社概要・所在地・代表者・事業・連絡先・更新状況
3. **法人情報** — 法人番号、法人種別、本店所在地、設立・状態（分かる範囲）
4. **官公庁情報** — 許認可・登録・行政処分・公表の有無
5. **業界団体** — 加盟・認定の有無（公式掲載で確認。自称のみは弱い証拠）
6. **ニュース・報道** — 直近の重要報道、トラブル、提携、経営変化
7. **口コミ・評判** — 傾向のみ。個別口コミは事実扱いにしない
8. **関連会社・関係団体** — 親子・グループ・同住所・同代表などの公開関係
9. **照合** — 矛盾・不一致を洗い出す
10. **分離** — 「確認できた事実」と「推測・評価」を分けて書く
11. **報告書作成** — 下記テンプレートで Markdown を出力

Web 検索・公式ページ取得を積極的に使う。確認できないことを埋めない。

## ルール

- **一次情報を優先**する
- **情報源を明記**する（サイト名、URL、確認日または取得時点）
- **確認できないことを推測で補わない**
- **事実と評価を混ぜない**（評価は専用セクションのみ）
- 口コミ・SNS・掲示板だけで違法性や悪質性を断定しない
- 個人の機微情報や非公開情報の探索はしない
- 不確かな点は「不明」「要追加確認」と書く

## 出力先

特に指定がなければ次へ保存する:

```text
00_temporary/YYYYMMDD_調査_<対象名>.md
```

- `YYYYMMDD` はローカル日付
- ファイル名に使えない文字は除去または `_` に置換
- チャットにも要約を返し、全文はファイルに書く
- ユーザーが別パスを指定したらそれに従う

## 進捗の示し方

長時間になりそうな場合は、調査中に短い進捗を出す:

```text
進捗:
- [ ] 対象の特定
- [ ] 公式サイト
- [ ] 法人情報
- [ ] 官公庁
- [ ] 業界団体
- [ ] ニュース
- [ ] 口コミ
- [ ] 照合・報告書
```

## 完了時

1. 報告書ファイルのパスを伝える
2. チャットではサマリー・主要な事実・疑わしい点・総合評価だけを短く返す
3. 事実と評価を混ぜて話さない

# Webサイトを持つ（Cloudflare）

## 結論

**Cloudflareを使うと、自分のWebサイトを公開できる。** 自分でサーバーを借りる必要はない。

- 最初は無料URL（`○○○.pages.dev`）で公開できる
- 独自ドメイン（`.com` / `.jp`）は年間数百〜数千円
- ログイン付きにできる。家族だけ見る介護情報サイトも作れる

作り方のイメージ: **Cursor / Claude Codeで中身を作る → Cloudflareで公開する**

---

## Cloudflareとは

WebサイトやAIアプリを、速く・安全に・安く動かすインターネット基盤。昔はCDN・セキュリティ会社、今はVercelやSupabaseに近い開発基盤でもある。

| 機能 | 役割 |
| --- | --- |
| DNS | ドメインとサーバーをつなぐ |
| CDN | 世界中から速く配信 |
| WAF | 攻撃を防ぐ |
| Pages | Webサイトを公開（Vercelに近い） |
| Workers | サーバーなしでプログラムを動かす |
| D1 | SQLデータベース |
| R2 | ファイル・画像（S3に近い。転送料が安い） |
| Workers AI / Vectorize | AI・検索 |

Workersを使うと、画面・API・認証・DB・ファイルをCloudflare側にまとめられる。Freeプランから試せる。

---

## サイトを持つ手順

1. **中身を作る**（HTMLなど。Claude Code / Cursorでも可）
2. **Cloudflareに置く**（Pages または Workers）
3. **住所を決める**（無料の `pages.dev` か、有料の独自ドメイン）

| URL | 例 | 料金 |
| --- | --- | --- |
| Cloudflareの無料URL | `xxxxx.pages.dev` | 無料 |
| 独自ドメイン | `xxxxx.com` / `xxxxx.jp` | 年間数百〜数千円 |

サイト公開そのものに、独自ドメインは必須ではない。

---

## ログイン・家族限定

ログインはできる。メール＋パスワード、Google、ワンタイムコードなど。人ごとに「全部見える / 一部だけ / 入れない」も分けられる。URLを知っていても、ログインしなければ中身は見えないようにできる。

### 母親の介護情報を家族だけ共有する例

- 病院・薬・通院・ケアマネ・書類・メモ・写真
- 自分と妻は編集、姉は閲覧のみ、など権限を分ける
- 医療情報なので、URL秘匿だけでは足りない。ログイン必須＋権限＋HTTPS＋DB側のアクセス制御が必要

この用途では **Cloudflare（公開・画面）＋ Supabase（ログイン・DB・ファイル）** が分かりやすい。

```
家族のスマホ・PC
    ↓
Cloudflare（サイト）
    ↓
Supabase（ログイン・介護情報・写真・PDF）
```

AIに「前回の血液検査は？」と聞く、といった拡張も後から足せる。

---

## Supabaseとの関係

| | 向いていること |
| --- | --- |
| **Supabase** | データベース・認証が中心 |
| **Cloudflare** | 公開・API・世界配信・サーバーレス |

どちらか一方ではなく、Cloudflareを手前、SupabaseをDB、と組める。

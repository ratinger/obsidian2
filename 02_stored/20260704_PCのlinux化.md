# 目的

Panasonic Let's note **CF-RZ4**（Win10・古いPC）を Linux 化し、**Hermes Agent の薄型クライアント**として使う。

- **推論（LLM）** → サーバーPCの LM Studio（`192.168.124.25:1234`）
- **ツール実行（シェル・ファイル等）** → CF-RZ4 上で実行

Open WebUI（`:3000`）は不要。LM Studio REST API 直結で足りる。

---

# 対象マシン：CF-RZ4 概要

| 項目 | 内容 |
|------|------|
| 機種 | Panasonic Let's note CF-RZ4（2014〜2015年頃） |
| CPU | Intel Core M-5Y10c / M-5Y70 / M-5Y71 等（ファンレス・低消費電力） |
| RAM | **4GB LPDDR3（はんだ実装・増設不可）** |
| ストレージ | M.2 2280 **SATA SSD**（128〜256GB。NVMe 非対応の報告あり） |
| ディスプレイ | 10.1型 WUXGA（1920×1200）IPS・静電容量タッチ |
| 無線 | Intel Dual Band Wireless-AC 7265 系（要 non-free ファームウェア） |
| その他 | USB3.0×3、HDMI、VGA、有線LAN、SDスロット |
| 物理スイッチ | 左側面 **Wi‑Fi ON/OFF スイッチ**あり |
| 重量 | 約745g |

### モデル差

- **Xi（LTE）モデル**は docomo UIM スロット・LTE モジュール内蔵。Linux では LTE は後回しでよい（Hermes 用途では LAN 優先）。
- 型番末尾で CPU・SSD 容量が異なる。BIOS 画面の「情報」タブで正確な型番を控える。

---

# 考慮すべき点

## 1. RAM 4GB が最大の制約

Hermes Agent は Python + Node.js +（ブラウザツール利用時）Chromium を使う。**4GB では常時快適とは限らない**。

| 対策 | 内容 |
|------|------|
| 軽量デスクトップ | Xubuntu / Lubuntu を選ぶ（GNOME フルは避ける） |
| zram / swap | インストール後に zram 有効化を検討 |
| ツールセット絞り | 最初は browser ツール無効、CLI 中心で試す |
| 同時起動を抑える | ブラウザ・GUI アプリを増やさない |

推論はサーバー側なので GPU は不要。**RAM とディスク I/O** がボトルネックになりやすい。

## 2. Hermes × リモート LM Studio

| 項目 | 内容 |
|------|------|
| 接続先 | `http://192.168.124.25:1234/v1`（自宅 LAN） |
| モデル名 | `google/gemma-4-e4b`（サーバー側と完全一致） |
| API Key | `lm-studio`（任意文字列で可） |
| レイテンシ | エージェントは LLM 往復が多い → **有線 LAN 推奨** |
| Tailscale | 外出先からは可能だが遅くなりやすい。自宅では LAN IP を使う |

Hermes のツールは **CF-RZ4 上のファイル・シェル** が対象。サーバーPCの Obsidian vault を触る場合は、SMB マウント等の別途設定が必要。

## 3. Linux 互換性（CF-RZ4）

海外ユーザーの報告では **Linux は概ね plug-and-play**（Debian 11 + non-free ISO で Wi‑Fi・Wi‑Fi スイッチ動作）。

| 機能 | 期待 | 備考 |
|------|------|------|
| Wi‑Fi | ○ | **non-free ファームウェア入り ISO** を使う |
| 有線 LAN | ○ | 最も安定。Hermes 運用は有線推奨 |
| タッチパネル | ○ | 多くの場合そのまま |
| 輝度キー（Fn+F2/F3） | △ | カーネル 6.1+ なら改善。ダメなら追加設定 |
| サウンド | ○〜△ | 機体差あり |
| バッテリー表示 | △ | tlp 導入で改善することが多い |
| LTE（Xi モデル） | ×〜△ | 優先度低 |

## 4. Win10 からの移行リスク

- Win10 サポート終了済み → Linux 化の動機として妥当
- **完全入れ替え前に Live USB で動作確認**（必須）
- リカバリ用に Win10 イメージまたは重要データのバックアップを別媒体へ
- SSD 丸ごと消すと Win10 に戻すのに再インストールが必要

## 5. USB 起動・BIOS（レッツノート共通）

機種・設定状態によって **UEFI 有効/無効** や **Boot Mode（通常/互換）** の組み合わせが異なる。Live USB が認識されない場合は以下を試す。

| 設定項目 | 試す値 |
|----------|--------|
| セキュアブート | **無効** |
| Boot Popup Menu | **有効**（一時的に起動デバイス選択） |
| Boot Mode | USB が見えない場合 **互換** に変更 |
| UEFI 起動 | 機体によって **有効/無効を切り替えて試す** |

電源 ON 直後から **F2**（Panasonic ロゴより前）で Setup Utility。保存は **F10**。

## 6. ストレージ

- 128GB でも Hermes 単体なら足りる
- 余裕が欲しければ **M.2 SATA SSD（2280）** へ換装可（NVMe は非対応の報告あり）
- 換装前に Live USB で新 SSD へ直接インストールも可

## 7. セキュリティ

Hermes は **コマンド実行・ファイル変更** を行うエージェント。

- CF-RZ4 専用機として割り切る
- 重要データ・SSH 鍵・パスワードマネージャは載せない
- サーバー PC の `:1234` は LAN 内のみ（Tailscale は VPN 内限定）

# 推奨構成

```text
[CF-RZ4: Linux + Hermes Agent]
  ├─ ツール実行（bash, ファイル, …）
  ├─ HTTP → 192.168.124.25:1234/v1
  └─ SSH ← サーバーPC / Tailscale から操作（GUI なし）
              ↓
[サーバーPC: Windows + LM Studio]
  └─ google/gemma-4-e4b（REST API :1234）
```

### 推奨 distro

| 順位 | distro | 理由 |
|------|--------|------|
| 1 | **Xubuntu 24.04 LTS** | 4GB 向け軽量 DE、LTS、日本語対応 |
| 2 | Lubuntu 24.04 LTS | さらに軽い |
| 3 | Debian 12 + Xfce（non-free firmware） | 実績あり（CF-RZ4 で Wi‑Fi 動作報告） |

**Ubuntu Desktop（GNOME フル）は非推奨**（4GB では重い）。

ISO は **「non-free ファームウェア同梱」版** を選ぶ（Intel Wi‑Fi 用）。

# 手順

## Phase 0：準備（サーバーPCまたは別マシンで）

### 0-1. バックアップ

- [ ] CF-RZ4 の個人ファイルを外付け SSD / サーバーPCへコピー
- [ ] ブラウザのブックマーク等、必要なものを退避
- [ ] （任意）Win10 リカバリ USB またはディスクイメージを確保

### 0-2. Live USB 作成

8GB 以上の USB メモリを用意。

**Windows（サーバーPC）で Rufus を使う例：**

1. [Xubuntu 24.04 LTS](https://xubuntu.org/download/) の ISO をダウンロード
2. [Rufus](https://rufus.ie/) で USB へ書き込み
3. パーティション構成：**GPT / UEFI** を選択（起動しない場合は MBR も試す）

---

## Phase 1：Live USB 起動テスト（インストール前・必須）

### 1-1. BIOS 設定

1. CF-RZ4 に USB を挿す
2. 電源 ON → すぐ **F2** 連打
3. **セキュリティ** タブ → セキュアブート **無効**
4. **起動** タブ → Boot Popup Menu **有効**
5. USB が認識されない場合：
   - Boot Mode を **互換** に変更、または
   - UEFI 起動の **有効/無効** を切り替え
6. **F10** で保存・再起動
7. 再起動時に Boot Menu（機種により F12 等）から USB を選択

### 1-2. Live 環境チェックリスト

「Try Xubuntu」で起動し、**インストールせず** 以下を確認：

| # | 確認項目 | OK |
|---|----------|-----|
| 1 | 画面表示・解像度（1920×1200） | ☐ |
| 2 | キーボード・タッチパッド | ☐ |
| 3 | タッチパネル（タップ反応） | ☐ |
| 4 | **有線 LAN** でインターネット | ☐ |
| 5 | **Wi‑Fi** 一覧に SSID 表示・接続 | ☐ |
| 6 | Wi‑Fi 物理スイッチ OFF→ON で切替 | ☐ |
| 7 | 輝度キー（Fn+F2/F3） | ☐ |
| 8 | サウンド（任意） | ☐ |
| 9 | `ping 192.168.124.25`（サーバーPC到達） | ☐ |

**5 または 9 が NG ならインストールしない。** 別 ISO（Debian non-free 等）で再テスト。

---

## Phase 2：インストール

1. Live デスクトップの「Install Xubuntu」を起動
2. 言語：**日本語**
3. キーボード：**日本語**
4. インストール種類：
   - **ディスク全体を消去**（CF-RZ4 専用機の場合）
   - デュアルブートにする場合は「その他」でパーティション手動（非推奨：4GB では Win+Linux は厳しい）
5. ユーザー名・パスワードを設定
6. インストール完了 → 再起動 → USB を抜く

### インストール直後

**Hermes より先に** システム更新と基本ツールを入れる。順番を守ること。

```bash
# 1. パッケージ一覧を更新
sudo apt update

# 2. アップグレード（推奨・Hermes 前に実施）
sudo apt upgrade -y

# 3. 基本ツール（Hermes インストールに必須）
sudo apt install -y git curl xz-utils build-essential
```

#### apt upgrade について

| 項目 | 内容 |
|------|------|
| やるべきか | **はい**。セキュリティ修正・カーネル更新が含まれる |
| 件数 | インストール直後で **50〜60 件程度** は普通（Ubuntu 24.04 noble） |
| 所要時間 | Core M + 4GB だと **10〜30 分** かかることも |
| 電源 | **AC 接続** のまま実行 |
| 再起動 | カーネル更新が入ったら **`sudo reboot`**（Wi‑Fi・輝度キーを再確認） |

Phase 2 まで完了していれば、Phase 3 では **3-1（Hermes インストール）から** でよい。

```bash
# 電源・バッテリー（任意）
sudo apt install -y tlp
sudo systemctl enable tlp

# zram（4GB 向け・任意）
sudo apt install -y zram-tools
```

### スリープ無効（Hermes 長時間タスク向け）

```bash
# 蓋を閉じてもスリープしない（電源接続時）
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

※ 携帯運用時は `unmask` して元に戻す。

## Phase 2.5：SSH（リモート接続）

CF-RZ4 を **サーバーPC や外出先からターミナル操作** するための設定。**GUI（デスクトップ画面のリモート表示）は当面使わない**（SSH は文字ベースのみ）。Hermes は `hermes chat` / `hermes --tui` を SSH 越しに実行する。

```text
[自宅 LAN]
  サーバーPC（192.168.124.25）──ssh──► CF-RZ4（192.168.124.??）

[外出先]
  ノートPC / スマホ ──Tailscale──► CF-RZ4（100.x.x.x）
```

関連: [[20260704_LMstudioの設定]]（Tailscale・LAN 構成）

### 方針

| 項目 | 内容 |
|------|------|
| 用途 | リモートから `hermes chat`、設定変更、ログ確認 |
| GUI | **当面なし**（RDP/VNC は 4GB では重い。必要になったら別途検討） |
| 外出先 | **Tailscale 経由**（ポート 22 をルーターに公開しない） |
| 秘密鍵 | **接続元（サーバーPC）に置く**。CF-RZ4 には載せない（§7 セキュリティ） |

### 2.5-1. CF-RZ4 で SSH サーバー有効化

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh   # active (running) を確認
```

LAN IP を控える：

```bash
hostname -I
# 例: 192.168.124.30
```

### 2.5-2. 自宅 LAN から接続（サーバーPC → CF-RZ4）

CF-RZ4 のインストール時に設定した **Linux ユーザー名** を使う。

**Windows（サーバーPC）PowerShell：**

```powershell
ssh ユーザー名@192.168.124.30
```

初回は fingerprint で `yes` → パスワード入力。

接続後の例：

```bash
hermes chat
curl http://192.168.124.25:1234/v1/models
```

### 2.5-3. 鍵認証（任意・推奨）

**サーバーPCで鍵を作成：**

```powershell
ssh-keygen -t ed25519 -C "server-pc-to-cfrz4"
```

**公開鍵を CF-RZ4 に登録：**

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh ユーザー名@192.168.124.30 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

以降はパスワードなしで `ssh ユーザー名@192.168.124.30`。

### 2.5-4. 外出先から（Tailscale）

LM Studio と同じ Tailscale アカウントを CF-RZ4 にも入れる。

**CF-RZ4：**

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
tailscale ip -4   # 例: 100.xxx.xxx.xx を控える
```

**外出先から：**

```powershell
ssh ユーザー名@100.xxx.xxx.xx
```

サーバーPC の Tailscale IP は [[20260704_LMstudioの設定]] 参照（`100.68.114.93`）。CF-RZ4 は `tailscale ip -4` で別 IP になる。

### 2.5-5. IP 固定（任意）

DHCP だと IP が変わることがある。ルーターで CF-RZ4 の MAC アドレスに **192.168.124.x 固定割当** を推奨。

```bash
ip link show   # 有線インターフェース名（例: enp0s25）を確認
```

### 2.5-6. ファイアウォール（Tailscale のみ SSH・任意）

LAN からも Tailscale 経由に統一する場合：

```bash
sudo ufw allow in on tailscale0 to any port 22
sudo ufw deny 22
sudo ufw enable
```

自宅 LAN（`192.168.124.0/24`）からも直接 SSH したい場合は ufw 設定は省略してよい（デフォルトで SSH は開いている）。

### 2.5-7. トラブル時

| 症状 | 確認 |
|------|------|
| Connection refused | `sudo systemctl status ssh`、CF-RZ4 電源 ON |
| Connection timed out | IP 正しいか、同一 LAN か、有線 LAN 接続か |
| Permission denied | ユーザー名・パスワード、`~/.ssh/authorized_keys` |
| 外出先から不可 | CF-RZ4 で `tailscale status`、両端 online か |

### 2.5-8. GUI が必要になったら（参考・未実施）

| 手段 | 用途 |
|------|------|
| VS Code Remote SSH | ファイル編集（軽量） |
| xrdp / VNC | デスクトップ全体（4GB では重い） |

当面は SSH + CLI/TUI で運用する。

## Phase 3：Hermes Agent セットアップ

### 3-0. 前提パッケージ（Hermes より先）

Hermes のインストールコマンド自体が **curl** を使う。Phase 2 の「インストール直後」を飛ばしていると `curl が見つかりません` になる。

**推奨順（Phase 2 を飛ばした場合）：**

```bash
sudo apt update
sudo apt upgrade -y          # 推奨。完了後、カーネル更新があれば reboot
sudo apt install -y git curl xz-utils build-essential
```

| パッケージ | 用途 |
|------------|------|
| `curl` | Hermes インストーラの取得（**必須**） |
| `git` | Hermes 本体の clone |
| `xz-utils` | インストーラが Node.js を `.tar.xz` で落とす |
| `build-essential` | Desktop 試行時に必要（CLI のみなら後回し可） |

確認：

```bash
curl --version
git --version
```

Phase 2（`apt update` → `upgrade` → 基本ツール）済みなら、この節は **確認だけ** で 3-1 へ進む。

### 3-1. インストール

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

新しいターミナルを開き：

```bash
hermes doctor
```

### 3-1.5. 初回セットアップ画面（インストール直後）

インストール完了後、`hermes setup` 相当の画面が出る。

```text
How would you like to set up Hermes?

  Quick Setup (Nous Portal)     … クラウド OAuth（API キー不要）
  Full setup                    … 自分でプロバイダ・ツールを設定
  Blank Slate                   … 最小構成から opt-in
```

**CF-RZ4 + リモート LM Studio では `Full setup` を選ぶ。**

| 選択肢 | 選ぶ？ | 理由 |
|--------|--------|------|
| Quick Setup (Nous Portal) | ✕ | クラウド経由。自宅 LM Studio 構成と合わない |
| **Full setup** | **◎** | LM Studio を `192.168.124.25:1234` に向けられる |
| Blank Slate | △ | 後から全部手動。Full setup の方が早い |

操作：`↓` で **Full setup** に移動 → `Enter` / `Space` で決定。

ウィザードを **ESC で抜けた**／**Quick Setup を選んでしまった** 場合：

```bash
hermes model    # プロバイダ再設定
# または
hermes setup    # ウィザードを最初から
```

### 3-1.6. Select terminal backend（ターミナル実行場所）

Full setup の途中で **「コマンドをどこで実行するか」** を聞かれる。

```text
Select terminal backend:

  Local          … このマシン上で直接実行（デフォルト）
  Docker         … 隔離コンテナ内
  Modal          … クラウド sandbox
  SSH            … 別のリモートマシン上
  Daytona        … クラウド開発環境
  Singularity    … HPC 向けコンテナ
  Keep current (local)
```

**意味：** Hermes が `ls` やファイル編集など **ツール（シェル）を実行する場所**。LLM（推論）の場所とは別。

```text
[CF-RZ4]  Hermes ──HTTP──► [サーバーPC] LM Studio（推論だけ）
              │
              └─ Local なら、コマンドは CF-RZ4 上で実行
```

**CF-RZ4 では `Local`（または `Keep current (local)`）のまま Enter。**

| 選択肢 | CF-RZ4 で選ぶ？ |
|--------|-----------------|
| **Local / Keep current (local)** | **◎** この PC 上でコマンド実行 |
| Docker | ✕ 4GB ではコンテナ追加で重い |
| SSH | △ 別マシンで実行したいときだけ（サーバーPC 等） |
| Modal / Daytona | ✕ クラウド。自宅 LM Studio 構成と無関係 |

### 3-1.7. Select platforms to configure（メッセージ連携）

Full setup の途中で **Discord / Slack / Telegram 等** の一覧が出る。Hermes を **チャットアプリから操作** するための設定（Messaging Gateway）。

```text
Select platforms to configure:

  Discord (not configured)
  Slack (not configured)
  Telegram (not configured)
  …
```

**今は Bot トークン等を用意していない → 何も選ばず Enter（または ESC でスキップ）。**

| 操作 | 意味 |
|------|------|
| Space | チェック ON/OFF |
| Enter（未選択のまま） | スキップして次へ |
| ESC | キャンセル |

**ターミナルの `hermes chat` とは別物。** Gateway なしでも CF-RZ4 のターミナルで Hermes と会話できる。Discord/Slack は「スマホやブラウザから Hermes に話しかける」用途。

#### 後で Discord / Slack を試すとき

準備ができてから：

```bash
hermes gateway setup   # 対話式。Discord / Slack を選択
hermes gateway         # ゲートウェイ起動（常駐）
```

| プラットフォーム | 事前に用意するもの |
|------------------|-------------------|
| **Discord** | [Discord Developer Portal](https://discord.com/developers/applications) で Bot 作成 → **Bot Token**、Message Content Intent 有効、自分の **User ID**（`DISCORD_ALLOWED_USERS`） |
| **Slack** | [api.slack.com/apps](https://api.slack.com/apps) で App 作成 → **Bot Token**（`xoxb-`）+ **App Token**（`xapp-`、Socket Mode）、自分の **User ID**（`SLACK_ALLOWED_USERS`） |

設定は `~/.hermes/.env` に保存される。CF-RZ4 が常時起動＋`hermes gateway` 常駐が前提。

参考: [Discord | Hermes Agent](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/discord) / [Messaging gateway](https://hermes-agent.nousresearch.com/docs/user-guide/messaging)

### 3-1.8. Tools for CLI（使える道具の選択）

Hermes が **CLI モードで使えるツール** を ON/OFF する画面。

```text
Tools for CLI

  [✓] Web Search & Scraping
  [✓] Browser Automation
  [✓] Terminal & Processes
  [✓] File Operations
  …
```

| 操作 | 意味 |
|------|------|
| Space | チェック ON/OFF |
| **Enter** | **この選択で確定して次へ** |
| **Esc** | **キャンセル**（確定しない。setup が途中で止まることも） |

**Esc ではなく Enter で確定する。** その前に CF-RZ4（4GB）向けに重いものを外すとよい。

#### CF-RZ4 向け推奨（Space で OFF にする）

| ツール | 推奨 | 理由 |
|--------|------|------|
| Terminal & Processes | **ON** | 基本。シェル実行 |
| File Operations | **ON** | 基本。ファイル読み書き |
| Memory / Skills / Todo 等 | ON | 軽め。エージェント本体 |
| Web Search & Scraping | **ON 可** | **DuckDuckGo（ddgs）なら API キー不要**（後述）。Browser より軽い |
| **Browser Automation** | **OFF** | Chromium 起動で RAM 逼迫 |
| Image Generation / TTS | OFF | API キー・重い |
| Video Analysis / Generation | OFF | 最初から OFF でよい |
| Computer Use | OFF | デスクトップ操作。4GB では不要 |
| X (Twitter) / Spotify 等 | OFF | 未設定なら OFF |

最初は **Terminal + File + Memory 系だけ ON** に絞り、慣れたら `hermes tools` で追加してもよい。

```bash
hermes tools    # 後からツールセットを変更
```

#### Web Search を ON にする場合（DuckDuckGo）

setup 中に **Select Search Provider** が出たら **DuckDuckGo (ddgs) [free · no key · search only]** を選ぶ（↓ で移動 → Enter）。

Nous Subscription / Firecrawl は **API キーまたは有料** のため、CF-RZ4 + 自宅 LM Studio 構成では選ばない。

setup を **Skip してしまった**／**後から変更** する場合：

```bash
hermes config set web.backend ddgs
```

または `~/.hermes/config.yaml`：

```yaml
web:
  backend: ddgs
```

| 項目 | 内容 |
|------|------|
| API キー | **不要** |
| できること | 検索（タイトル・URL・スニペット） |
| できないこと | **ページ全文取得**（`web_extract`）。必要なら Browser や別 API |
| パッケージ | 初回利用時に `ddgs` を lazy-install することが多い。失敗したら venv 内で `pip install ddgs` |

```bash
# 動作確認（hermes chat 内で「今日の東京の天気を調べて」等）
hermes chat
```

CF-RZ4 では **Web Search ON + Browser Automation OFF** の組み合わせが現実的。

#### Web Search（ddgs）と web_extract の違い — 運用メモ

| ツール | ddgs で | 実際の挙動 |
|--------|---------|------------|
| `web_search` | ○ | キーワード検索 → タイトル・URL・スニペット（**海老名天気の概要は取れる**） |
| `web_extract` | ✕ | URL からページ全文取得。**ddgs は search-only** で必ず失敗 |

Hermes が「DDG が動いていない」と言った場合、**検索は動いているが extract 用バックエンドが無い** のが正確。

**Weathernews / Yahoo 天気を「ページから読む」** 系タスクは、現構成（ddgs のみ・Browser OFF）では **ほぼ無理** に近い。JS 描画＋アンチボットのため、単純スクレイピングも安定しない。

##### 現実的な回避策（API キーなし〜）

1. **検索スニペットで足りる** — 「今日の海老名 曇り 26℃」程度なら `web_search` だけで可（最初のやり取りは成功）
2. **無料天気 API + terminal** — Hermes の Terminal ツールで `curl`（スクレイピングではなく API）

```bash
# 海老名付近（Open-Meteo・キー不要）の例
curl -s 'https://api.open-meteo.com/v1/forecast?latitude=35.4464&longitude=139.3906&current=temperature_2m,weather_code&daily=temperature_2m_max,precipitation_probability_max&timezone=Asia%2FTokyo'
```

`hermes chat` では「Open-Meteo API を curl で叩いて海老名の天気を教えて」と指示すると terminal 経由で取れる。

3. **Browser Automation を ON**（RAM に余裕があるとき）— Chromium で Weathernews を開いて読む。CF-RZ4 4GB では重い
4. **web_extract 用バックエンド** — Firecrawl / Tavily / Exa 等（API キー要）。または Firecrawl 自前 Docker（サーバーPC向け）

##### Hermes への指示例（extract 不要）

```text
web_extract は使わず、web_search のスニペットだけで答えて。
```

```text
Weathernews の URL は開かず、Open-Meteo API を curl で取得して海老名の今日の天気を教えて。
```

### 3-1.9. Choose a provider（TTS・音声読み上げ）

**Text-to-Speech（音声合成）** のプロバイダを **1つだけ** 選ぶ画面。ツール画面のような複数 ON/OFF ではない（ラジオボタン）。

```text
Choose a provider:

  Microsoft Edge TTS [recommended · free]   … API キー不要
  OpenAI TTS / ElevenLabs …                 … 有料・API キー要
  KittenTTS / Piper [local · free]          … ローカル ONNX
  Skip – configure later
```

| 選び方 | 向いている人 |
|--------|--------------|
| **Microsoft Edge TTS**（一番上） | 無料・API キー不要で TTS を使いたい → **Enter でこれで OK** |
| **Skip** | 音声は不要（`hermes chat` テキストだけ）→ いちばん軽い |

**音声を使わないなら Skip でよい。** 使うなら **一番上の Microsoft Edge TTS** が CF-RZ4 向き（クラウド経由だが軽量・キー不要。Linux でも Edge ブラウザ本体は不要）。

ローカル完結にしたい場合のみ **Piper** や **KittenTTS**（声データ DL で数十 MB）。

Tools で **Text-to-Speech を OFF** にしているなら、ここは **Skip** でも矛盾しない。

### 3-3.1. コンテキスト 8192 エラー（64K 未満）

`hermes chat` で次のエラーが出る場合：

```text
Model google/gemma-4-e4b has a context window of 8,192 tokens,
which is below the minimum 64,000 required by Hermes Agent.
```

**原因：** LM Studio がモデルのコンテキストを **8192** と報告している。Hermes Agent は **最低 64,000 トークン** が必須（ツール定義・システムプロンプトが大きいため）。

gemma-4-e4b 自体は **128K 対応** だが、LM Studio 側の設定が低いままになっている。

#### 手順 A：サーバーPC（LM Studio）側 — 本命

サーバーPC（`192.168.124.25`）で LM Studio を操作：

1. モデル `google/gemma-4-e4b` をロード
2. モデル選択横の **⚙（歯車）** → **Context Length** を **65536**（または **64000**）に変更
3. **モデルを再ロード**（Unload → Load、または設定反映のため再起動）
4. REST API（:1234）が **Running** のままか確認

CLI（`lms` がある場合）：

```powershell
lms load google/gemma-4-e4b --context-length 65536
lms server start --port 1234
```

※ 64K コンテキストは **サーバーPC の VRAM/RAM を多く使う**。OOM や極端な遅延が出たら 65536 で様子を見る。

#### 手順 B：CF-RZ4（Hermes）側 — 上書き指定

API がまだ 8192 と返す場合、Hermes に実際の値を教える：

```bash
hermes config set model.context_length 65536
```

または `~/.hermes/config.yaml`：

```yaml
model:
  default: google/gemma-4-e4b
  provider: lmstudio
  base_url: http://192.168.124.25:1234/v1
  context_length: 65536
```

**A と B の両方** やるのが確実。

#### 確認

```bash
hermes chat
```

ステータスバーに **64K 前後** のコンテキストが表示され、先ほどのエラーが消えれば OK。

#### それでもダメな場合

| 症状 | 対処 |
|------|------|
| サーバーPCで LM Studio が OOM | コンテキストを 65536 に下げる、またはより小さい **tool 対応モデル** に変更 |
| Hermes が依然 8192 と表示 | モデル再ロード後 `curl .../v1/models` で返る値を確認；`context_length: 65536` を再設定 |
| gemma-4-e4b が agent として弱い | モデル変更を検討（サーバーPCの VRAM に合わせて Qwen 等） |

# Hermes Desktop（GUI）について

2026年6月頃、Hermes Agent に **Desktop アプリ**（macOS / Windows / Linux）が public preview として追加された。CLI と同じ config・セッション・スキルを共有するネイティブ GUI。

CF-RZ4 では **CLI 確立後のオプション** として検討する（Phase 3 を先に完了させる）。

---

## 動くか？

| 観点 | CF-RZ4 での評価 |
|------|-----------------|
| Linux サポート | ○ あり（public preview） |
| リモート LM Studio 接続 | ○ CLI と同じ `base_url` 設定で可 |
| 4GB RAM で快適 | △〜× **Electron が重い** |

推論はサーバーPC（`192.168.124.25:1234`）側で行うため GPU は不要。ただし Desktop 自体が **Electron（Chromium）+ Hermes バックエンド（Python + Node）** を CF-RZ4 上で動かすため、RAM 4GB ではスワップ頼み・OOM のリスクがある。

公式 Platform Support でも Linux の Tier 1 推奨は **`install.sh`（CLI）** で、Desktop ワンクリックインストーラーは **macOS / Windows** が主。

---

## Linux でのインストール

Windows/macOS の `.exe` / `.dmg` とは異なり、**ターミナル経由**。

```bash
# CLI + Desktop 一括
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --include-desktop

# すでに CLI がある場合
hermes desktop
```

前提（Desktop 用に追加）:

```bash
sudo apt install -y build-essential
```

初回 `hermes desktop` は **Electron アプリをビルド**する。Core M + 4GB では **10〜30分以上** かかる・フリーズ気味になることがある。

AppImage は [GitHub Releases](https://github.com/NousResearch/hermes-agent/releases) に **あるときとないとき** がある。ビルド済みが無ければ `hermes desktop` がソースから組み立てる。

---

## リモート LM Studio 設定

Desktop も CLI と **同じ `~/.hermes/config.yaml`** を使う。Phase 3 で設定済みならそのまま Desktop からも接続される。

| 項目 | 値 |
|------|-----|
| Provider | `lmstudio` |
| Base URL | `http://192.168.124.25:1234/v1` |
| Model | `google/gemma-4-e4b` |
| API Key | `lm-studio` |

Settings → Model から GUI でも変更可能。CLI で設定したセッションは Desktop から再開できる（逆も同様）。

## CF-RZ4 向けの使い分け

| 優先度 | 手段 | RAM 負荷 | 向き |
|--------|------|----------|------|
| 1 | `hermes chat` | 低 | ◎ 日常使い |
| 2 | `hermes --tui` | 中 | ○ GUI っぽく使いたいとき |
| 3 | `hermes desktop` | **高** | △ 余裕があれば試す |

### Desktop を試す場合の注意

- **browser ツールは OFF**（Chromium が二重になる）
- 起動前後で `free -h` を確認
- zram 有効化済みであること
- 他の GUI アプリ（Firefox 等）を閉じてから起動
- 重い・落ちる → **CLI / TUI に戻す**（Desktop 必須ではない）

### GUI が欲しいが CF-RZ4 が厳しい場合

- **サーバーPC（Windows）** で Hermes Desktop + リモート LM Studio（LM Link または LAN `:1234`）
- CF-RZ4 は **CLI のみ** の薄型クライアントに割り切る

# やらない方がよいこと

| 項目 | 理由 |
|------|------|
| CF-RZ4 に LM Studio を入れる | CPU/GPU/RAM 不足。推論はサーバーPCへ |
| WSL2 on Win10 で Hermes | 古い 4GB マシンでは Linux ネイティブより重い |
| Ubuntu GNOME フル | 4GB では DE だけで RAM を消費 |
| Live テストを飛ばしてインストール | Wi‑Fi/Boot 問題は機体差が大きい |
| Hermes に browser ツールを最初から ON | Chromium で RAM 逼迫 |
| CF-RZ4 で Hermes Desktop を日常使い | Electron + バックエンドで 4GB 逼迫。CLI/TUI 優先 |

# 結論

CF-RZ4 は **4GB・Core M** という制約があるが、**Hermes 薄型クライアント＋リモート LM Studio** という用途には向いている。Linux 化の実績も CF-RZ4 系であり、**non-free ISO + Live USB 事前確認** が成功の鍵。

distro は **Xubuntu 24.04 LTS**、ネットワークは **有線 LAN 優先**、Hermes は **CLI 中心・browser ツールは後回し** が現実的な進め方。GUI が欲しくても **Hermes Desktop は CF-RZ4 ではオプション**（重ければ TUI またはサーバーPC側 Desktop）。
